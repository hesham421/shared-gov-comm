I couldn't run `gov.py analyze` or `gov.py split --dry-run` because the toolkit isn't in this repo, so the ALIGN rows say "pending" and the `self-check` block keeps the `findings: 0, clean: true` placeholder for the orchestrator to stamp.

**Files written**
- `P3_1/backend-execution-plan-cat.md`, about 2,600 lines:
  - **Structure:** the seven phases in profile order. SVC-API is split into CRUD / SEARCH / INT groups, and DATA-DOM into MASTER / LOOKUP.
  - **Contents:** 51 endpoints, 70 queries and 57 error codes (49 business rules plus 8 platform-standard ones). All 161 database fields are bound, plus the `totals`, `permission-matrix`, `bootstrap` and `error-catalog` blocks.
  - **INT-C:** it's the last phase but has no blocks, because the cross-module register is empty and nothing new was added.
- `P3_1/registry-exec-be-cat.md`: id ranges (next free API-CAT-052 and QR-CAT-071), the endpoint list with permissions and contract items, totals and the ADR list.
- `P3_1/api-spec-cat.yaml`: OpenAPI 3.1.0 with 51 operations on 33 paths. It passes `openapi-spec-validator`, and every one of the 57 error codes is answered by its status and code.
- `change-manifest.md`: added entries for the plan (API-CAT-001…051 and QR-CAT-001…070), the registry and the API document, plus a P3.1 note.
- ADR-CAT-044 to 048 in `analysis/decisions/CAT/`, all accepted and non-breaking, none blocked. The ambiguity rule requires them, but they are outside the four listed files.

**Decisions to review**
- **Five endpoints not in the SRS:** read Variant, read Item unit, read Variant attribute, the storefront read and the catalogue search. I added them so every contract operation and every screen operation has an endpoint. Other modules reach the same data through one in-process interface, `CatalogueReadApi` (ADR-CAT-045).
- **Catalogue search without permission:** it returns an empty list rather than "forbidden", as REQ-CAT-127 asks.
- **Role grants:** the default grants for Owner, Seller/cashier and Warehouse staff follow the SRS screen tables. I couldn't tell from the inputs how the core security module records grants, so the implementer has to confirm the mechanism (ADR-CAT-046).
- **Race protection:** operations that decide on several rows of one Item lock the Item row first. Category moves, and barcode adds versus scale-layout creates, take a per-tenant lock. Optimistic version checks protect updates (ADR-CAT-047).
