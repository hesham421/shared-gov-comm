**Decisions to review**

These three ADRs in `analysis/decisions/CAT/` are files outside the brief's list. I wrote them because the brief's ambiguity rule requires an ADR there, and the plan cites them. All three are ACCEPTED (non-breaking).
- **ADR-CAT-049 (biggest design choice):** the backend commits each child line (unit, barcode, image, variant…) through its own endpoint. To keep one save per screen, the Items page queues child changes and its single Save sends them in a fixed order. It stops at the first rejection and keeps the unsent lines pending. Publish, deactivate and the other record commands run on their own, and only when there are no unsaved changes.
- **ADR-CAT-050:** lookups, flags and images come from erp-core, not from any CAT endpoint, so they are recorded as UXDs rather than invented CAT APIs.
- **ADR-CAT-051:**
  - Two operations are deliberately not called by any CAT screen: API-CAT-011 (read Item unit) and API-CAT-046 (storefront read). They show as ✗ in the coverage table, citing this ADR.
  - The Bundle component picker uses Items search plus Item read instead of API-CAT-042. API-CAT-042 needs the Barcode-labels permission, which an Items editor may not have.

The next free ADR is ADR-CAT-052. No questions were raised and nothing is BLOCKED.
