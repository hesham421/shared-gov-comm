I wrote the P3.1 backend execution plan for INV v1, its registry and the API document. I couldn't find `gov.py`, so neither `gov.py analyze` nor the split dry-run has been run yet. What I did check, with my own read-only scripts: the API document is valid OpenAPI 3.1.0, and the plan, the API document and the error catalog match each other with no mismatches.

**What the three files contain**
- **`backend-execution-plan-inv.md`**:
  - **Front sections:** an index with the totals (DBF 219 · XM 13 · API 51 · QR 46), the full text of all 48 rules, a table binding all 219 database fields, 46 query entries and 56 error codes.
  - **The seven phases, in profile order:** CORE, DATA-DOM, SVC-API (split into CRUD / SEARCH / INT), DOC, SEC-BE, ALIGN-BE, and INT-C last.
  - **SEC-BE:** a permission matrix for 12 screens and a bootstrap list of 50 rows. Every permission there has a role and a source.
  - **INT-C:** 15 integration blocks. 13 are the edges already registered and 2 are new (XM-INV-014 and XM-INV-015, reads of Variant and Item state).
- **`registry-exec-be-inv.md`**: the API and QR ranges, the endpoint and query tables, which block honours each of the 21 contract items, the two new integration edges ready to be registered, and the ADR list.
- **`api-spec-inv.yaml`**: one operation per API block, with the same method, path and traces, and an error response for every catalog code.

**Results of my checks**
- 79 start/end markers, all paired.
- Outside INT-C, no line names CAT's tables, operations or ids.
- All 138 requirements are covered by at least one endpoint or database field.
- Every required column has a writing endpoint or a stated reason none does.
- Every query is used by at least one endpoint, and the reverse holds.

**Things to know before the gate**
1. **I wrote files outside the three listed.** ADR-INV-021 … 031 are in `analysis/decisions/INV/`. The brief's ambiguity rule asks for ADRs there, and the check that cited ADRs exist on disk is critical, so I treated that folder as allowed. Remove them if you disagree.
