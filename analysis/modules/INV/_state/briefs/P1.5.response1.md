I've written the INV v1 contract to `C:\repos\commerce\governance-shared\analysis\modules\INV\P1_5\contract-inv.md`. I haven't run `gov.py analyze`; the brief leaves that to the orchestrator.

The contract has 21 items, numbered CON-INV-001 to CON-INV-021 with no gaps:

- **5 entity promises:**
  - **Warehouse and Branch:** each has a code as its business key and its identifier, both `BIGINT`, and a "notify, never cascade" rule when one is deactivated.
  - **Lot:** keyed by Variant plus lot number.
  - **Stock balance:** keyed by Variant, warehouse and lot.
  - **Stock valuation:** one record per Variant.

  Each one lists its consumers, and any consumer's hard foreign-key column copies `BIGINT` exactly.
- **16 operations and events:** one item per row of the SRS table of operations offered to other modules (section A8). They cover reading and listing warehouses and branches, availability, reserve, release, reservations of a document, receive, issue, valuation, lot, Item stock settings, and the capability turn-off check. The two events are the stock-move event and the warehouse/branch change event. Each has a signature only: name, inputs, output and errors by meaning, with no path or verb. Each also notes how capability flags change it, which RULEs apply, and which ENT and REQ it traces to.
- **Given-usage block:** the SRS's 12 rows copied word for word, in the same order.
- **Also included:** conventions that apply to every operation (`BIGINT` identifiers, base unit and decimal places, idempotency keys, source documents held as references with no foreign key), a stability section, a decisions table and a self-check.

Three choices you might not expect:

- **Reservation and Stock move stay private.** Callers keep `reservationPk` and `stockMovePk` only as references with no foreign key.
- **Item stock settings stays private too.** Other modules see it only through the read answers of the settings read and the turn-off check.
- **The valuation read returns zeros for a Variant that has never been valued**, instead of "not found". This matches how the SRS handles availability for a Variant that never moved (REQ-INV-041).
