I've written the PTY v1 contract to `analysis/modules/PTY/P1_5/contract-pty.md`, with 24 items numbered CON-PTY-001 … 024 and no gaps. I didn't run `gov.py analyze`, because the orchestrator runs it after this stage.

- **Entities (001–005):** Party, Customer, Supplier, Address and Credit override request. Each names its business key and its identifier, and every identifier is typed BIGINT.
- **Lookups (006–008):** the customer group and address type lists, which are open to new values. Also the three closed credit code sets that consumers can branch on; adding a value to those counts as a breaking change.
- **Operations (009–020, 023–024):** one item for each consumer operation in the SRS A8.1 table, with inputs, output and errors only (no paths or verbs). These cover reading customers and suppliers, the walk-in customer, guest checkout, the credit check, the override requests, the credit switch-off count and the global search. I also added Customer and Supplier registration, because the SRS has a sale or purchase document register a party without leaving it (REQ-PTY-008).
- **Event (021):** the notice sent when a Customer or Supplier is deactivated.
- **Extension point (022):** the hook other modules implement to report a Customer's open balance; it has a 3-second timeout.
- **Given usage:** the block is copied from the SRS row for row, in the same order.
- **Supporting sections:** a table of which consuming module may depend on which items, the rules for additive and breaking changes, and a self-check.

Three choices you might want to review:
- **Address read by identifier (CON-PTY-012):** this is not in the A8.1 table. I added it because AC-PTY-039 needs a deactivated Address to stay readable by its identifier.
- **Customer and Supplier reads return `partyFk`:** REQ-PTY-002 doesn't list this field. I included it because A8.1 says the read returns the Customer entity, and consumers need it to request that party's addresses. Because the SRS already supports this, I didn't write an ADR.
- **The `forNewDocument` input on the reads:** this flag is how the contract shows the inactive-party refusal (RULE-PTY-005) without blocking reads of older documents.

No ADR was needed and I didn't create any other files.
